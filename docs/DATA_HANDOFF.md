### 접근 방법

- 저장소는 코드만 담는다. **실행 데이터는 별도로 전달**한다.
  전달 수단은 자유다 — 각자 실행하면 `파일럿_실행데이터.zip`(약 36MB) 한 번 배포,
  공용 클라우드에서 함께 실행하면 공용 경로에 한 번 두면 된다.
  **핵심은 수단이 아니라 모두가 같은 버전의 데이터를 쓰는 것**이다.
- 무결성 확인용 SHA-256 앞 16자:
  `fc2ffc802c91692b…` telegram · `1ca06ab5214b587c…` factiva
- 받은 파일은 위 경로 그대로 두면 코드가 찾는다.
- 키는 **환경변수**로 넣는다: `OPENAI_API_KEY`, `DART_API_KEY`.
  설정은 `cp config_kr.example.yaml config_kr.yaml`. 실제 설정 파일은
  `.gitignore`에 있어 **커밋되지 않는다**.

## 2. 판단 시점에 이용 가능한 자료만 제공하는 규칙 (as-of)

판단 시각은 **08:30 KST(개장 전)** 이다.

| 소스 | 규칙 |
|---|---|
| 텔레그램 | `date_utc < 판단일 전일 23:30Z` (= 08:30 KST 이전), 직전 2일치를 팩터 원료로 |
| Factiva | `pd_date < 판단일` (D+1 규칙) |
| DART | `Available From` 기준. 공시 **접수일이 아니라 이용 가능 시각** |
| 가격 | **전 거래일까지**. 판단일 당일 시가는 아직 없다 |

### 콘테스트 쪽 추가 규칙 (누수 차단)

보상 계산에 필요한 **모든 데이터의 이용 가능 시각 ≤ 판단 시각**이어야 한다.

- 보상 = 신호일 시가 → **다음 거래일** 시가.
  따라서 판단일 `D`의 이력에 `D-1` 신호를 넣으면 **`D` 당일 시가**가 필요해진다.
  → 이력은 **두 거래일 전까지**(KRX 거래일 기준, 휴장은 자연히 제외).
- 날짜 간격이 아니라 **확정 시각**으로 거른다: `contest/researcher/reward_availability.py`
- 학습 모델 파일도 같은 규칙: `train_meta.json`의 학습 as-of가 판단 **시각**보다
  뒤면 로드를 거부한다.
- 판정기(`research_signal_judger`)의 과거 보상 입력에도 같은 규칙을 적용했다.

## 3. 알려진 결함 (고치지 않고 기록한 것 포함)

| 결함 | 상태 |
|---|---|
| `judger_id`가 로그에만 쓰여 5회가 **동일 설정의 반복** | 기록. 관측 표본 38건 중 12건에서만 반복 간 차이가 났다 |
| 출력의 `from_source` 라벨이 실제 출처와 어긋나는 사례 | 기록. **라벨을 믿지 말고 원문 대조**할 것 |
| `action` 필드에 서술문이 들어가는 형식 실패 | 집계에서 정상 신호·기권과 **분리해서** 센다 |
| 전원 0가중일 때 확률 합성이 정의되지 않음 | 동일가중 대체 + 그 사실 기록. '기권'이라 부르지 않는다 |
| 학습 신호와 평가 판단의 **모델이 혼재** | 미팅 안건 2 |
| Factiva 구간이 2026-05~07뿐 | 미팅 안건 1 |

### 고친 실행 차단 결함 (변경 내역)

- 콘테스트 이력 창이 `D-1`까지라 당일 시가를 요구하던 누수 → `D-2`(거래일)로 차단
- 과거 신호가 **정상 기권**이면 보상 계산이 예외를 던져 콘테스트가 중단 → `reward=None`
- 예측기의 `abs(None)` 크래시 → None 가드
- `has_contest_data()`가 `reward` 키를 요구해 judge 특징만 주입하면 학습기가 건너뜀
- `run_contest_c3`가 트리거 시각을 09:00으로 고정 → 인자화
- scikit-learn 미설치로 LightGBM 로드 실패 → 설치

## 5. ⚠️ Factiva 공유 조건 확인 — 전달 전 선행

Factiva는 구독 계약이 있다. **기존 구독의 팀 공유 허용 범위를 확인한 뒤** 전달해야
한다. 드라이브든 공용 서버든 이 조건은 같다.

- 허용되면: 압축 배포 또는 공용 경로 중 편한 쪽
- 제한되면: 각자 자기 계정으로 내보내거나, 공용 환경에서만 접근하도록 제한

텔레그램 수집분은 이 제약이 없다.
