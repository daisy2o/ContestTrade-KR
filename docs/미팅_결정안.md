# 화요일 미팅 결정안 — 본실험 설계 확정

산출물은 긴 회의록이 아니라 **확정 설계 1장 + 담당자·완료일**이면 충분하다.
안건을 네 묶음으로 제한한다. 각 항목은 **고르면 끝나는 형태**로 적었다.

---

## 1. 연구 범위

### 1-A. 기간

| 안 | 내용 | 필요 작업 | 위험 |
|---|---|---|---|
| **A1** | 확보한 **2026-05~07**로 진행 | 없음 (바로 실행) | 구간이 짧아 날짜 수가 제한됨 |
| **A2** | 원래 계획대로 **2025-01~** | **Factiva 추가 내보내기** 선행 | 누가 언제 확보할지 미정 |
| A3 | 2026-05~07로 먼저 하고 나중에 확장 | 없음 | 두 번 실행 |

> 현재 Factiva 보유 범위는 **2026-05-01 ~ 2026-07-01**이다. 텔레그램은 2024년부터
> 있지만 뉴스 없이 파이프라인이 성립하지 않아 함께 쓸 수 없다.

### 1-B. 종목군

| 안 | 내용 |
|---|---|
| **B1** | **8종목 유지** (D32, 지도교수 지시 "전 종목 다 모으고 시작하지 말 것") |
| B2 | 30종목(ktop30)으로 확대 |
| B3 | 8종목으로 본실험 후 확장 검토 |

> 8종목 결과를 KOSPI200으로 일반화하거나 PIT 유니버스 연구 완료로 쓰지 않는다.

## 2. C3의 정확한 정의

### 2-A. 학습 창 · 재학습 주기 · 최소 학습량

현재 잠정값: 학습 창 180일 / 재학습 5일 / 최소 표본 30건 / 이력 창 5일 + 예측 3일.

| 안 | 내용 |
|---|---|
| **C1** | 현재 값 유지하고 **사전 고정** |
| C2 | 최소 표본을 올림(예: 100건) — 준비 구간이 길어짐 |
| C3 | 이력·예측 창을 줄여 표본을 늘림 — 메커니즘이 바뀜 |

> 참고: 최소 파일럿에서 **실제 학습 표본 30건에 트리 분기 932개**가 나왔다.
> 표본당 31배로 **과적합 신호**다. 정규화 파라미터를 사전 고정할지 함께 정한다.

### 2-B. 0가중 처리

전원 0가중이면 확률 합성(가중치 합 = 1)이 **정의되지 않는다**.

| 안 | 내용 |
|---|---|
| **D1** | **동일가중 대체** + 날짜별 기록 (현재 방식) |
| D2 | 그날을 평가에서 제외 — 조건 간 분모가 달라짐 |
| D3 | 전 종목 0.5로 처리 — '예측 없음'으로 간주 |

> 전원 0가중을 곧바로 '기권'이라 부르지 않는다. `max(0,û)` 절단의 결과일 수 있고,
> **동일가중 예측을 내는 것과 거래에서 현금으로 기권하는 것은 다르다.**

### 2-C. 학습 신호의 모델 통일

현재 **혼재**: 과거 학습 신호는 상위 gpt-4o-mini + 최종 판단이 날짜별로 섞임,
평가일 판단은 gpt-4.1. **학습·평가 분포가 다르다.**

| 안 | 내용 | 비용 |
|---|---|---|
| **E1** | 학습 신호도 **gpt-4.1로 통일** — 준비 구간 재생성 | 준비일 × 3에이전트 판단 호출 |
| E2 | 현재 혼재 유지하고 한계로 명시 | 없음 |
| E3 | 학습·평가 모두 gpt-4o-mini로 통일 | 평가일 재생성 |

## 3. 평가 설계

### 3-A. 주 비교와 주평가

| 항목 | 현재 안 | 확정? |
|---|---|---|
| 주 비교 | **C3 대 C2(동일가중)** | |
| 주평가 | **Brier** (가중 합성한 상승 확률, 오차에 가중치 재적용 안 함) | |
| 집계 | 날짜별 종목 평균 → 날짜 동일가중 평균 | |

### 3-B. 함께 보고할 것

- **C1**(단일 에이전트) — 세 belief를 각각 보고, 사후 최고 선택 금지
- **C4**(셔플) — **순열별 채점 후 평균** (= C2 + 순열 분산). 확률을 먼저 평균하면 C2와 항등
- **제출 범위·기권** — 0.5 기준선(=0.25)과 함께. 평가 단위는 (날짜, 종목)
- **형식·실행 실패** — 기권과 분리
- **실행비용** — C3의 judge 호출 등 조건별 추가분

### 3-C. 수익 평가를 할 것인가

하려면 아래를 **사전에** 정해야 한다.

- 체결 시점 (판단일 시가?) · 보유 기간 (다음 거래일 시가 청산?)
- 비중 규칙 (가중치를 그대로 비중으로? 상한은?)
- 거래비용 가정 (수수료·슬리피지)
- 기권의 거래상 의미 (현금 보유?)

| 안 | 내용 |
|---|---|
| **F1** | 이번엔 **Brier만**, 수익은 탐색 결과로도 내지 않음 |
| F2 | 위 규칙을 정하고 **탐색 결과로만** 보고 |
| F3 | 수익을 주평가로 승격 — D2(판단 품질 중심)와 충돌 |

## 4. 실행과 발표 분담

| 역할 | 내용 | 담당 | 완료일 |
|---|---|---|---|
| 입력 준비 | 구간 재생, 데이터 스냅샷 공유 | | |
| 본실험 실행 | **한 번만 생성**해 공유 | | |
| 평가·검토 | 같은 결과를 각자 검토 | | |
| 발표 자료 | 예비 결과 + 확정 설계 | | |

> 공통 결과는 한 번 생성해 공유하고, 팀원은 **같은 결과를 검토**한다.
> 각자 전체 실험을 반복하지 않는다.

## 미팅 후 순서 (참고)

1. 합의 사항을 코드·설정에 반영하고 **버전 고정**
2. 필요한 학습 이력 준비 + 짧은 통합 점검
   (C1~C4가 같은 출력을 쓰는가 · LightGBM 경로가 실제로 도는가 · 실패/폴백이 구분되는가)
3. **본실험 실행 — 결과를 보며 조건이나 날짜를 바꾸지 않는다.**
   수정에 쓴 날짜는 개발 자료로 구분하고, 사전에 정한 평가 구간에서 비교한다.
   반복 수와 예산도 시작 전에 고정한다.
4. 결과 분석·정리 — 콘테스트가 좋든 나쁘든 **그대로** 보고. 날짜별 차이·제출 범위·
   폴백·실행비용을 함께 본다.
