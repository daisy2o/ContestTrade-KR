# 본실험 설계 — 경쟁 메커니즘 비교 (고정판 초안 v1)

연구 질문: **경쟁 메커니즘이 판단 품질에 기여하는가.**
텔레그램 포함/제외는 **데이터 파트의 준비 작업**으로 종료하고, 필요할 때 하는
보조 실험으로 남긴다.

---

## 0. 먼저 확정 — 경쟁은 어느 단계에 작용하는가

**코드 확인 결과: 집계 단계에만 작용한다. 토론·수정·추가 추론은 없다.**

`ResearchContest.run_research_contest(trigger_time, current_signals)`는 **이미 생성된**
신호를 인자로 받아 다음만 한다.

1. 과거 신호 로드 → 2. 과거 신호 보상 계산 → 3. **당일 신호에 LLM judge 점수 부여**
→ 4. 예측(샤프) → 5. 가중치 산출 → 6. 저장

에이전트 쪽에서 콘테스트 결과(`optimized_weights`·`final_result`)를 읽는 경로는 없다
(`agents/`·`data_source/` 전수 확인). 따라서:

> **같은 저장 출력을 네 조건에서 재사용할 수 있다.** 집계 방식의 효과를 비교하기에
> 적합한 구조다.

**단, 3단계는 LLM 호출을 발생시킨다.** 신호 내용을 바꾸지는 않지만 콘테스트 조건에만
드는 **추가 실행비용**이므로 비용 차감 평가에 반영한다.

⚠️ 이 확인은 현재 코드 기준이다. 콘테스트가 토론·수정을 유발하도록 바꾸면
**집계 효과와 판단이 바뀌는 효과를 분리해야 하며**, 그때는 이 설계가 더 이상
전체 효과를 측정하지 못한다.

---

## 1. 주 비교

> **콘테스트 대 동일가중 앙상블.**

단일 에이전트 대비 우위만으로는 부족하다. **동일가중 앙상블보다 나아야**
"여러 판단을 모아서 얻은 효과" 이상의 기여를 주장할 수 있다.

---

## 2. 조건 구현 — 같은 에이전트 출력에서 무엇만 바뀌는가

모든 조건이 **같은 시점·같은 자료·같은 에이전트 판단**을 쓴다. 바뀌는 것은
신호에 부여되는 가중치뿐이다.

| 조건 | 가중치 | 바꾸는 것 | 사전 확정 사항 |
|---|---|---|---|
| **C1 단일 에이전트** | 해당 에이전트 신호만 사용 | 에이전트 집합 | **사후에 가장 잘한 에이전트를 고르지 않는다.** 세 belief를 각각 별도 조건으로 전부 보고하고, 대표값이 필요하면 **세 조건의 평균**을 쓴다 |
| **C2 동일가중 앙상블** | 유효 신호에 균등 | 없음(균등) | 정규화·netting 규칙을 C3와 동일하게 |
| **C3 콘테스트** | `w_i = max(0,û_i)/Σmax(0,û_j)` | 가중치 산출 | judge 호출 비용을 별도 기록 |
| **C4 셔플 대조** | C3의 가중치 **벡터를 그대로 두고 에이전트에 재배정** | 가중치↔에이전트 연결 | **보존**: 가중치 값의 분포, 신호 집합, 날짜 / **파괴**: 어느 에이전트가 어느 가중치를 받는가. 날짜별로 섞고 시드 고정 |

C4의 목적: **가중치 분포 자체의 효과**(예: 집중도)와 **경쟁이 고른 연결**의 효과를 가른다.
C3 ≈ C4이면 "경쟁이 고른 것"이 아니라 "가중치가 한쪽으로 쏠린 것"이 효과의 원인이다.

포트폴리오 구성 규칙(netting·포지션 수·정규화)은 **네 조건 모두 동일하게** 사전 명세한다.

## 3. 평가

### 주평가 후보

**Brier score** — 방향 적중만이 아니라 **확률 보정**까지 반영한다.
신호의 `probability`가 "평가 구간에서 선택 방향이 맞을 확률"로 정의돼 있으므로(D51)
그대로 쓸 수 있다.

가중치를 반영해야 조건 간 차이가 정의된다(D22a): 신호 단위 정확도는 기저 신호가
같으므로 조건 간 차이가 정의상 0이다. **가중 Brier**를 주평가로 둔다.

### 보조 평가 — 함께 보고

| 지표 | 왜 |
|---|---|
| 방향 적중률(가중) | 해석이 쉬운 대조 지표 |
| 추천 범위(커버리지) | 조건별 종목 수·중복도. 선택적 예측이라 커버리지를 통제해야 비교가 성립 |
| 기권율 | C3는 예측 점수가 전부 ≤0이면 전량 0가중 → 조건 특이적 결측 발생(D22a) |
| 형식 실패율 | 정상 신호·기권과 **분리**해 센다 |
| 수익 성과 | 거래비용 차감 후. **탐색 결과로만** 보고 |
| 실행비용 | C3의 judge 호출 등 조건별 추가 비용 |

### 기준선

동일비중 항상매수 대비 **초과분**으로 보고한다(D50). WDA 단독 보고 금지.

## 4. 시간 규칙

| 항목 | 규칙 |
|---|---|
| 판단 시각 | **08:30 KST** (개장 전) |
| as-of | telegram `date_utc < 전일 23:30Z` · Factiva `pd_date < 판단일` · 가격 전 거래일까지 |
| 예측 대상 구간 | 판단일 시가 → **다음 거래일** 시가 |
| 체결 | 판단일 시가. 청산 다음 거래일 시가 |
| **경쟁 점수 갱신 시점** | 아래 ⚠️ 참조 |

### ⚠️ 발견한 누수 — 반드시 고치고 시작한다

현재 구현은 판단일 `D`의 콘테스트에서 **이력 창을 `D-1`까지** 잡고
(`load_historical_signals`: `D - 1일`까지의 거래일), 각 신호의 보상을
**신호일 시가 → 다음 거래일 시가**로 계산한다(`calculate_signal_reward`).

그러면 `D-1` 신호의 보상이 **`D` 당일 시가**를 필요로 한다.
`D 08:30`은 개장 전이므로 **그 값은 아직 존재하지 않는다.**

> **수정 규칙: 이력 창은 `D-2`에서 끝낸다.**
> 신호일 `S`의 보상은 `S+1` 시가를 쓰므로, `D 08:30`에 확정돼 있으려면
> `S+1 ≤ D-1`, 즉 **`S ≤ D-2`** 여야 한다.

이 수정은 C3·C4에만 영향을 준다(C1·C2는 과거 성과를 쓰지 않는다).
수정 전 결과는 본실험 결과로 쓰지 않는다.

## 5. 공통 기반 — 비교 조건이 아니다

| 항목 | 고정값 |
|---|---|
| 최종 판단 모델 | `gpt-4.1-2025-04-14` (D64) |
| 상위 단계(팩터 요약·계획·도구 선택) | 현재 설정 유지 |
| 데이터 | Factiva · DART · 텔레그램 · 가격 |
| 근거 구조 | A(자유 서술) |
| 평가 기준 | rubric v2 |

네 조건이 **같은 시점의 같은 자료와 같은 에이전트 판단**을 쓴다.

## 6. 재사용할 기반

- 입력 재생(`backtest_runner`) — 날짜별 저장 입력 생성
- 버전 고정(`PILOT_VERSION.md`·`llm_judgment`) — 판단 단계만 교체
- 근거 추적(`trace_telegram`·`link_to_source_msg`·`DETECTION_RULE.md`) — 근거가 입력에서
  왔는지 원문까지 확인
- 오프라인 재집계(`run_contest_c3`) — 재생 1회 + 집계 오프라인(D18)
