# 근거 감사 판정 기준 (v2 — 2026-09-24 개정)

라운드마다 기준이 흔들려 오류율 비교가 불가능해졌던 문제를 막기 위해 고정한다.
**이 문서를 바꾸면 이전 감사 결과와의 비교가 끊긴다** — 변경 시 버전을 올리고,
이전 출력도 새 기준으로 재평가한 뒤에만 비교한다.

## 변경 이력

- **v2 (2026-09-24)**: v1로 수행한 3일 감사의 메타 검증에서 감사자 간 기준 적용이
  갈린 것이 확인돼 개정. 가장 큰 이탈은 "출처 라벨 오기"를 한 감사자만 축 fail로
  처리해 특정 날짜의 오류율 비교 부호가 뒤집힌 것. v1 결과는 재판정본
  (`audit_consistency_check.json`)을 적용해야 v2와 비교 가능.
- v1 (2026-09-24): 최초 고정.

## 1. 판정 축 (8축, 각각 pass / fail / n/a)

| 축 | 통과 조건 |
|---|---|
| 회사 | 수치·사건이 귀속된 회사가 원문과 동일 (합산→개별, 계열사 혼동 없음) |
| 지표 | 지표 종류 동일 (매출≠영업이익, D램≠낸드≠HBM, 점유율≠순위) |
| 단위 | 원/달러, %/배/비율, 억/조 정확 |
| 기간 | 비교 창 동일 (1일/5일/20일, 분기, 연간) — 도구 창 변경 금지 |
| 사건 시각 | 사건이 일어난 날짜가 원문과 동일 (발행일·이용가능일로 대체 금지) |
| 방향 | 상승/하락, 증가/감소, 흑자/적자, 초과/미달이 원문과 동일 |
| 한정어 | 아래 2절 규칙에 따름 |
| 실제 입력 출처 | 그 수치·주장이 해당 실행의 입력(배경정보·도구 출력)에 **존재**하는지만 판정 |

> **[v2] 실제 입력 출처 축은 라벨을 판정하지 않는다.** `from_source` 오기재
> (도구값을 뉴스 출처로 표기하는 등)는 이 축 fail로 쓰지 말고, 별도 지표
> `출처_라벨_오기`로만 집계한다. 수치가 입력에 있으면 라벨이 틀려도 이 축은 pass.

## 2. 한정어 취급 — 2분류 (뭉뚱그리지 말 것)

- **사실 오류(fail)**: 한정어를 제거한 결과 **틀린 명제**가 되는 경우.
  - 장중 수치를 "종가·마감·기준가"라는 **단어로 본문에 명시**
  - 세그먼트 수치를 전체 시장 수치로 **명시** (낸드 18% → "반도체 점유율 18%")
  - 전망을 확정 실적으로, 합산을 개별 회사 수치로 **명시**
  - 기간 한정("지난해", "1분기")을 다른 기간으로 **이동**
- **시점·범위 불명확(flag, fail 아님)**: 한정어가 빠졌으나 틀렸다고 단정할 수 없는 경우.
  - 장중 수치를 종가라 말하지 않고 "기록했다"로만 서술
  - 기간을 명시하지 않은 채 "상승했다"

> **[v2] 한정어 fail은 본문 문자열 기준으로만 판정한다.** "종가·마감·기준가"라는
> 단어가 본문에 있을 때만 fail. 수치 조합이 어긋난 경우(다른 날 등락률 + 이 날 가격)는
> 한정어가 아니라 **지표 또는 사건시각 축**으로 처리한다.

## 3. 최종 verdict

- **주장확인**: 8축 전부 pass
- **사실오류**: 1개 축 이상 fail
- **불명확**: fail 없고 flag 1개 이상
- **원문미발견**: as-of 범위 내 어떤 원문·도구 출력으로도 뒷받침 안 됨
- **모호**: 판정 불가 (사유 기재)

### [v2] flag 종류 (fail 아님, 별도 집계)

| flag | 정의 |
|---|---|
| `시점_불명확` | 2절의 불명확 사례 |
| `해석_불지지` | 수치·방향은 정확한데 평가어("안정적", "회복 초기", "강세")의 **비교 기준이 입력에 제시되지 않은** 경우. 방향 축 fail로 쓰지 말 것 — 방향 축은 상승/하락·증감·흑자/적자·초과/미달만 다룬다 |
| `태그_이용가능일` | 본문에 날짜 주장이 없는데 `<time>` 태그만 이용가능일(D+1)인 경우. **flag는 부여하되 불명확 집계에서 제외**하고 이 카운트로만 보고 |

## 4. as-of 규율

- 텔레그램: `date_utc < 판단일 08:30 KST - 9h`
- Factiva: `pd_date < 판단일` (D+1 규칙)
- 가격 도구: 판단일 **전 거래일**까지
- 위반 발견 시 verdict와 별개로 `asof_violation: true` 표기
- **[v2]** 본문에 날짜 주장이 없고 태그만 이용가능일인 것은 사건시각 fail이 아니며,
  불명확으로도 집계하지 않는다 (§3의 `태그_이용가능일`로만).

## 5. 집계 시 함께 보고할 것

오류율만 보고하면 "문제 있는 출력을 많이 버려 좋아 보이는" 왜곡이 가능하다.
따라서 항상 병기한다:

- 근거 총수 / 사실오류율 / 불명확율 / 원문미발견율
- **제외율**: 감사에서 근거 자격을 잃은 비율
- **기권율**: 신호 자체를 내지 않은 에이전트·일자 비율
- **오류 포함 신호 수** (근거 오류가 신호로 전파된 정도)
- 신호 수, 에이전트별 분포
- `출처_라벨_오기`, `해석_불지지`, `태그_이용가능일` 각 카운트

> **[v2] 제외 근거의 분자·분모 규칙**: 유니버스 위반 등으로 제외된 신호의 근거는
> 오류율 **분자·분모 양쪽에서 빼고**, 제외 전/후 오류율을 병기한다 (이중계상 방지).

> **[v2] 입력 결함 기인 표기**: 도구·팩터의 결함이 원인인 오류는 판정은 사실오류로
> 하되 `input_defect_induced: true`를 병기한다. 세트 간 비교에서 에이전트 귀책과
> 구분하기 위함.

## 6. 비교 규율

- 조건·라운드 간 비교는 **같은 기준 버전**으로 평가한 결과끼리만.
- 감사자에게 어느 쪽이 수정본인지 **알리지 않는다**(블라인드).
- 기존 확인 오류는 회귀 사례로 고정하되, **신규 오류 전수 탐색을 대체하지 않는다**.

## 7. [v2] 출력 메타 스키마 (필수)

감사 결과 JSON에는 반드시 다음을 포함한다. 규약이 파일마다 달라 사후에야
불일치가 드러나는 일을 막기 위함이다.

```json
"meta": {
  "rubric_version": "v2",
  "판정규약": ["적용한 세부 규칙을 문장으로 나열"],
  "제외_처리": "분자·분모에서 제외했는지 여부"
}
```
