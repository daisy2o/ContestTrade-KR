# 파일럿 고정 버전 (P1)

실험마다 구조가 바뀌면 결과 차이를 무엇에 귀속할지 알 수 없다. 여기서부터는
아래 묶음을 **고정**하고, 이 버전의 출력만 P1 결과로 취급한다.

## 고정 대상

| 항목 | 고정값 |
|---|---|
| 판단 시각 | 08:30 KST (as-of: telegram `date_utc < 전일 23:30Z`, Factiva `pd_date < 판단일`, 가격은 전 거래일까지) |
| 판단 모델 | `gpt-4o-mini` (provider openai, thinking 미사용) |
| 근거 구조 | **A (자유 서술)** |
| 데이터 소스 | `kr_dart_disclosure`, `kr_factiva_news`, `kr_telegram_research` |
| belief | `config/belief_list_kr.json` 3종 (이벤트 드리븐 / 리서치 추종 / 가격·수급) |
| 유니버스 | `data_collection/universe/ktop30.csv` + `aliases_ktop30.csv` |
| 평가 기준 | `AUDIT_RUBRIC.md` v2 |

### 구조 A를 고른 이유

A/B 오류율 순위로 고르지 않았다. **탐지력이 비대칭이라 그 순위는 비교 근거가 못 된다**
— `ref_mismatch`는 구조 B에서만 관측 가능하고, A의 출처 라벨은 4종뿐이라 같은 오류라도
덜 잡힌다. 구조 B의 오류율이 더 높게 나오더라도 그것이 "B가 더 부정확하다"는 뜻인지
"B에서 더 잘 보인다"는 뜻인지 이 설계로는 가르지 못한다.

고른 근거는 세 조건이다.

1. **입력 시점과 원문을 추적할 수 있음** — A·B 모두 고정 입력(`background_information`
   + `tool_call_context`)에서 재실행하므로 동일.
2. **실행 실패·무효 참조·기권을 구별할 수 있음** — `consistency_checks.py`가 코드로
   분리. A에는 무효 참조 개념이 없어 구별 대상이 하나 줄지만, 형식 실패와 기권은
   양쪽 모두 구분된다.
3. **비교 조건에 같은 처리 규칙을 적용할 수 있음** — A가 upstream 기본 출력 형식이라
   C2/C3 집계·채점기에 추가 배선 없이 들어간다. B는 `expand_B`를 거쳐야 하고,
   그 경로가 아직 본실험 파이프라인에 연결돼 있지 않다.

구조 B는 **검수 실험용으로 유지**한다. 잘못된 근거 연결을 드러내는 데는 B가 필요하다.

## 이번 고정에서 고친 결함

명백하고 재현되는 것만 고쳤다. 남은 의미 오류를 없애려는 반복 수정은 멈춘다.

- `run_contest_c3.py`가 트리거 시각을 `09:00:00`으로 고정하고 `*_09-00-00.json`만
  찾던 문제. 파일럿 기본값이 08:30이라 리포트를 0건 찾았다. → 인자화, 0건일 때 경고.
- `verifier_bench.call()`이 호출자가 넘긴 프롬프트를 무시하고 자기 프롬프트를 쓰던 문제.
  라벨 체계가 어긋나 채점이 전부 '보류'로 떨어졌다. → `prompt` 인자 추가, 라벨 불일치는
  조용히 넘기지 않고 실행 실패로 기록.
- `build_review_set.py`가 `flags`만 보고 분류해, 사유 문장에만 `해석_불지지`가 적힌
  사례를 '정상'으로 넣던 문제. → 사유 문장도 함께 판독.
- 검수 입력에 종목명 없이 6자리 코드만 주던 문제. 검수 모델이 코드를 자기 기억으로
  회사에 연결하다 틀렸다. → `ktop30.csv`에서 종목명 주입.
- 수치 귀속에서 쉼표 표기를 정규화하지 않던 문제. 모델은 `268,500`으로 쓰고 도구
  출력은 `268500.0`으로 담고 있어, 실재하는 수치가 '어느 소스에도 없음'으로
  잘못 집계됐다. → `attribute_evidence.py`에서 정규화 후 비교.

## 고치지 않고 한계로 남긴 것

- 평가어("높은 편", "긍정적")의 비교 기준 부재 → `해석_불지지`로 기록만 하고 문제로
  세지 않는다 (rubric v2).
- belief 준수 측정은 rubric v2 규칙 6 아래에서 **변별력이 없다**. 파일럿 결과에
  belief 준수 지표를 싣지 않는다.
- 자동 검수 모델은 채택 기준 미달 시 쓰지 않고 **사람이 확인**한다. 검수 모델 성공은
  파일럿 진행의 전제 조건이 아니다.

## 이 버전으로 할 것

P1 파일럿: 같은 날짜·같은 유니버스에서 **텔레그램 포함/제외** 비교
(`evaluation/telegram_ablation.py`). C2/C3(콘테스트 온·오프)는 같은 재생본의
**집계 방식** 차이이고 입력이 같다. 이 파일럿은 **입력** 차이다. 두 축을 한 비교에
섞지 않는다.
