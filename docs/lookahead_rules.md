# Look-ahead 방지 규칙

## 기준 시각

- **시그널 확정**: 거래일 D 08:30 (KST). 이 시각까지 관측 가능한 정보만 D 시그널에 쓴다.
- **체결 가정**: D 시가(09:00 동시호가 체결가). 시가는 체결가로만 쓰고 피처로는 쓰지 않는다.
- D 08:30 이후에 생긴 정보는 모두 D+1 시그널로 넘긴다.

## 소스별 컷오프

| 소스 | D 시그널에 사용 가능한 조건 | 그 외 | 비고 |
| :-- | :-- | :-- | :-- |
| DART 공시 | 접수 시각이 있고 **시각 ≤ D 08:30** → D | 접수 시각이 08:30 이후 → **D+1** | OpenDART `list.json`은 접수 **일자만** 제공. 시각이 없으면 접수일 D 공시는 **D+1**에 사용 (보수적). KIND 공시 시각으로 `rcept_time`을 보완하면 위 규칙 적용 |
| Factiva 뉴스 (한경·매경·서울경제) | **pub_date ≤ D-1** | pub_date = D 이상 → D+1 이후 | RTF 내보내기에는 일자만 신뢰 가능. D 조간 기사도 D-1 게재분까지만 |
| 수급·시세 (pykrx) | **D-1 종가·D-1 투자자별 순매수까지** | D 당일 시세·수급은 사용 금지 | 시가총액·지수도 D-1 기준. D 시가는 체결가 전용 |
| 텔레그램 (증권사 리서치 4채널) | **메시지 시각 < D 08:30** | 08:30 이후 메시지 → D+1 | 포워딩 메시지는 채널 게시 시각 기준(원문 시각 아님). 편집된 메시지는 원 게시 시각 기준 |

## 구현 규칙

1. 모든 어댑터는 `trigger_time`(= D 08:30)을 입력으로 받고, 위 컷오프를 SQL `WHERE` 절에 직접 건다. 어댑터 밖에서 필터링하지 않는다.
2. 날짜 컬럼은 문자열 `YYYY-MM-DD`, 시각 컬럼은 `HH:MM`(KST)로 통일한다. 시각이 없는 소스는 `NULL`로 두고 D+1 규칙을 적용한다.
3. D-1은 **직전 거래일**이다. 주말·휴장일은 `market.sqlite`의 `prices` 테이블에 존재하는 날짜로 판정한다.
4. 백필·재수집 후에는 `collected_at`이 아니라 **원 게시/접수 시각**을 기준으로 필터한다.

## 검증 쿼리 예시

```sql
-- DART: 시각이 없는 공시가 접수일 당일 시그널에 들어갔는지 (0건이어야 함)
SELECT COUNT(*) FROM disclosures
WHERE rcept_time IS NULL AND rcept_dt = :D;

-- Factiva: D 당일 이후 기사 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM factiva_articles
WHERE pub_date >= :D;

-- 시세: D 당일 행 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM prices
WHERE date >= :D;

-- 텔레그램: D 08:30 이후 메시지 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM telegram_messages
WHERE msg_datetime >= :D || ' 08:30';
```

어댑터 단독 테스트에서 위 네 쿼리가 모두 0건임을 확인한 뒤 `python -m cli.main run`을 돌린다.
