# 현황 공유와 논의가 필요한 것 — 2026-09-25

데이터 파트를 하다가 콘테스트 실행 경로가 막혀 있어 거기까지 손을 댔습니다.
**지금까지 확인한 것**과 **아직 정해지지 않은 것**을 정리합니다.
정해지지 않은 것들은 제가 임의로 고르지 않았습니다 — 함께 정하면 좋겠습니다.

---

## 1. 지금까지 확인한 것

- 한국 시장 어댑터(DART·Factiva·텔레그램·가격)가 붙고 as-of 규칙이 적용됩니다.
- 콘테스트 실행 경로가 막혀 있어 수리했습니다. 네 조건(단일·동일가중·콘테스트·셔플)이
  같은 에이전트 출력으로 끝까지 비교됩니다.
- 시점 누수 두 곳을 찾아 막았습니다(보상 확정 시각, 학습 모델 시점).
- 소규모 예비 실행을 마쳤습니다. **수치는 저장소에 두지 않고 따로 공유합니다.**

실행 방법은 `TEAM_RUN_GUIDE.md`, 데이터 사정과 알려진 결함은 `DATA_HANDOFF.md`에
있습니다.

## 2. 아직 정해지지 않은 것

### 연구 범위

- 현재 Factiva 보유 범위가 **2026-05-01 ~ 2026-07-01**입니다. 뉴스 없이 파이프라인이
  성립하지 않아, 원래 계획한 2025-01~ 구간은 **추가 내보내기 없이는 불가능**합니다.
  이 구간으로 갈지, 확보한 범위로 갈지.
- 종목군을 8종목(D32)으로 둘지 넓힐지.

### 콘테스트(C3)를 어떻게 정의할지

- 학습 창·재학습 주기·최소 학습량. 현재 잠정값은 학습 창 180일 / 재학습 5일 /
  이력 5일 + 예측 3일입니다.
- **학습 자료 중복**: 수집 코드가 날짜마다 창을 통째로 모아 같은 (날짜, 에이전트)가
  여러 번 들어갑니다. 중복이 학습에 영향을 줍니다. 어떻게 다룰지.
- **전원 0가중일 때**: 확률 합성이 정의되지 않습니다. 지금은 동일가중으로 대체하고
  그 사실을 기록해 뒀는데, 이대로 둘지.
- **학습 신호와 평가 판단의 모델이 다릅니다.** 통일할지, 한계로 남길지.

### 평가 입력과 확률 제출 범위

- 저장 출력에 **서로 다른 버전이 섞여 있습니다.** 같은 (날짜, 에이전트)에 트리거
  시각이 다른 산출물이 함께 있고, 한쪽에는 `p_up`이 없습니다. 원인은 커밋·프롬프트
  기록으로 확인해야 합니다. **비교 가능한 실행 목록을 먼저 확정**할 필요가 있습니다.
- 현재 방식은 **추천한 종목에만 확률을 제출**합니다. 전체 8종목의 확률과
  추천·기권을 별도로 받을지 논의합니다.
  → 이는 프롬프트 조정이 아니라 **모델에게 요구하는 과제를 바꾸는 설계 변경**입니다.
- 방식을 변경하면 **별도 실험 버전으로 관리**합니다. 기존 예비 결과는
  **개발 점검 자료로 유지**합니다.
- **평가 코드 수정과 자료 정리를 누가 맡을지** 정합니다.

### 평가를 어떻게 할지

- 주 비교를 콘테스트 대 동일가중으로, 주평가를 Brier로 둘지.
- 단일 에이전트·셔플·제출 범위·기권을 어떻게 함께 볼지.
- 수익 성과를 볼지. 보려면 체결·보유·비중·비용 규칙을 미리 정해야 합니다.

### 역할

지금은 제가 만든 부분이 많습니다. **어떻게 나눌지 함께 정했으면 합니다.**
