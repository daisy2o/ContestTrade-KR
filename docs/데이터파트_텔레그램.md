## 1. 채널 선정

증권사 리서치 텔레그램 **4개 채널**을 씁니다.

| 채널 | 수집량 | 기간 |
|---|---|---|
| `shinhanresearch` | 13,246건 | 2024-01-01 ~ 2026-09-23 |
| `kiwoomresearch` | 9,146건 | 2024-01-01 ~ 2026-09-23 |
| `meritz_research` | 8,328건 | 2024-01-01 ~ 2026-09-22 |
| `hanaresearch` | 8,162건 | 2024-01-01 ~ 2026-09-23 |
| **합계** | **38,882건** | |

**고른 기준**: 증권사 공식 리서치 채널이면서 ① 종목명·코드가 본문에 직접 나오고
② 목표주가·실적 전망 같은 판단 재료가 있으며 ③ 수집이 끊기지 않는 것.

**이미지만 있는 메시지는 제외**합니다 — 본문이 없어 팩터 원료가 되지 못합니다
(채널별 4~27% 비중, 2026-09-21 실데이터 점검).

> 채널 구성은 바꿀 수 있습니다. 늘리거나 줄이면 그때 다시 정리하겠습니다.

## 2. 수집 데이터

`data_collection/data/telegram/telegram_research.sqlite` (93MB)

| 칼럼 | 내용 |
|---|---|
| `channel` · `message_id` | 메시지 식별 |
| `date_utc` | 서버 타임스탬프(UTC) — **판단 시점 필터의 기준** |
| `text` | 본문 |
| `is_forward` · `views` · `collected_at` | 부가 정보 |

수집기: `data_collection/telegram_collector.py`

### 판단 시점 규칙

판단 시각은 **08:30 KST(개장 전)** 입니다. 그 시각에 **이미 나와 있던 메시지만**
씁니다.

```
date_utc < 판단일 전일 23:30Z   (= 판단일 08:30 KST)
직전 2거래일치를 팩터 원료로 사용
```

## 3. 종목 매칭 규칙

`data_source/kr_telegram_research.py`의 `tag_stock_codes()`. **NLP를 쓰지 않고
규칙 기반 2단계**입니다 — 리서치 채널 메시지 상당수가 "종목명(코드)" 형태로
코드를 직접 포함하는 것을 실데이터에서 확인했기 때문입니다.

**1단계 — 6자리 코드 직접 매칭.** 본문의 `\b\d{6}\b`를 찾아 유니버스에 있으면 태깅.

**2단계 — 종목명·별칭 매칭.** 코드가 이미 발견됐어도 **다른 종목의 이름 언급은
계속 찾습니다**(예: "삼성전자(005930)와 하이닉스 비교" → 둘 다). 긴 표기 우선.

### 별칭 표 (`data_collection/universe/aliases_ktop30.csv`, 32개)

약칭·생략 표기를 정식 종목에 연결합니다. 예: `삼전`→삼성전자, `하이닉스`→SK하이닉스.

**제외어 가드**가 핵심입니다. 별칭이 더 긴 회사명의 일부로 나온 경우를 걸러냅니다.

| 별칭 | 제외어 |
|---|---|
| 포스코 | 포스코퓨처엠 · 포스코인터내셔널 · 포스코DX · 포스코이앤씨 · 포스코스틸리온 |
| 카카오 | 카카오뱅크 · 카카오페이 · 카카오게임즈 · 카카오모빌리티 |
| 현대차 | 현대차증권 |
| 현대건설 | 현대건설기계 |
| 미래에셋 | 미래에셋자산운용 |
| 아모레 | 아모레G |

제외어를 **지운 뒤 남은 본문에서** 별칭을 다시 찾습니다. 그래서
"현대차증권: 현대차 목표가 상향"은 현대차로 **정상 매핑**됩니다 — 제외어 때문에
독립적인 언급까지 죽지 않습니다.

### 자회사는 별도 (`subsidiaries_ktop30.csv`)

`국민은행 → KB금융` 같은 연결은 표로만 두고 **기본 태깅에 쓰지 않습니다.**
별칭(같은 회사의 다른 표기)과 자회사(다른 법인)는 성격이 달라서입니다.
자회사 정보를 넣으면 결과가 달라지는지는 별도 민감도 분석 대상입니다.

## 4. 매칭 결과

홀드아웃 3일(2026-05-11 · 06-12 · 07-01) 기준입니다.

```
as-of 창 메시지 224건 → 유니버스 종목 매핑 61건(27%) → 팩터 선별 54건
```

매핑되지 않은 73%는 대부분 **유니버스 밖 종목이거나 시황 일반론**입니다.
8종목만 보고 있으므로 낮은 비율 자체는 예상된 값입니다.

매칭된 내용이 최종 판단까지 실제로 전달되는지도 확인했습니다 — 미사용 10일 전부에서
텔레그램 고유 정보가 출력 근거로 쓰였고, 후보 전건이 **그 호출의 입력과 sqlite 원문
양쪽**에서 확인됐습니다(텔레그램 제외 조건에서는 0건).

> 이것은 **데이터가 끝까지 전달·사용된다는 확인**이지, 텔레그램이 성과를 개선한다는
> 결과가 아닙니다. 추천의 일관된 변화는 확인하지 못했습니다.

## 5. 알려진 한계

| 한계 | 내용 |
|---|---|
| **유니버스 밖은 매핑 안 됨** | 8종목(또는 ktop30) 밖 언급은 버려집니다 |
| **별칭 표가 수작업** | 새 표기가 나오면 추가해야 합니다. 자동 학습하지 않습니다 |
| **동음이의 위험** | 제외어로 막고 있지만 표에 없는 조합은 오매핑될 수 있습니다 |
| **이미지 전용 메시지 제외** | 차트·표만 있는 메시지의 정보는 들어가지 않습니다 |
| **채널 4개가 전부** | 이 4개에 없는 리서치는 반영되지 않습니다 |
| **Factiva 구간이 짧음** | 텔레그램은 2024년부터 있지만 뉴스가 2026-05~07뿐이라, 함께 쓸 수 있는 구간이 그만큼입니다 |

## 6. 팀원이 쓰는 방법

> 아래 절차는 **새 환경에서 처음부터 돌려 검증한 것이 아닙니다.**
> 한 번 해보시고 막히는 곳을 알려주시면 고치겠습니다.

### 받기

```bash
git clone -b feat/HJ https://github.com/daisy2o/ContestTrade-KR.git
cd ContestTrade-KR
uv venv && source .venv/bin/activate
uv pip install -r requirements.txt        # 기본
uv pip install -r requirements_kr.txt     # KR 추가

export OPENAI_API_KEY="sk-..."            # 키는 환경변수로 (YAML에 쓰지 말 것)
export DART_API_KEY="..." 
```

데이터는 GitHub에 없습니다. `파일럿_실행데이터.zip`(텔레그램 + Factiva)을 따로 받아 풉니다.

> 🔒 **Factiva는 유료 구독 자료입니다. 팀 세 명 밖으로 전달하지 마세요.**

```bash
mkdir -p data_collection/data/telegram data_collection/data/factiva
unzip -o ~/Downloads/파일럿_실행데이터.zip -d /tmp/pilotdata
mv /tmp/pilotdata/telegram_research.sqlite data_collection/data/telegram/
mv /tmp/pilotdata/factiva_news.sqlite      data_collection/data/factiva/
cp config_kr.example.yaml config_kr.yaml
```

**모두 같은 데이터를 써야 결과를 비교할 수 있습니다.** 같은 파일인지는 해시로
확인할 수 있습니다.

```bash
shasum -a 256 data_collection/data/*/*.sqlite
# telegram fc2ffc802c91692b… / factiva 1ca06ab5214b587c… 로 시작하면 같은 파일
```

### 텔레그램 데이터 직접 보기

```bash
sqlite3 data_collection/data/telegram/telegram_research.sqlite \
  "select channel, date_utc, substr(text,1,80) from messages
   where date_utc like '2026-06-15%' limit 5;"
```

### 종목 매칭 확인해 보기

```bash
cd contest_trade
CONTEST_TRADE_MARKET=KR-Stock python - <<'PY'
import sys
sys.path.insert(0, '.')
from data_source.kr_telegram_research import tag_stock_codes
from utils.kr_universe import load_universe, load_alias_table

names = load_universe()
alias = load_alias_table(names)

for t in ["삼성전자(005930) 목표주가 상향",
          "현대차증권: 현대차 2분기 실적 전망",
          "카카오뱅크 실적 호조",
          "삼전·하이닉스 동반 강세"]:
    hit = [names[c] for c in tag_stock_codes(t, names, alias)]
    print(f"{t}\n  → {hit or '매핑 없음'}\n")
PY
```

실행 결과:

```
삼성전자(005930) 목표주가 상향     → ['삼성전자']
현대차증권: 현대차 2분기 실적 전망  → ['현대차']
카카오뱅크 실적 호조              → 매핑 없음
삼전·하이닉스 동반 강세           → ['SK하이닉스', '삼성전자']
```

세 번째는 **카카오뱅크가 유니버스 밖이라 매핑 없음**이 정상입니다.
두 번째는 제외어 가드가 작동해 **현대차만** 잡혀야 합니다.
